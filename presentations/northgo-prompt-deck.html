先讓 AI 看懂整個網站

原始提示詞
分析 httpswww.northgo.com 生成網站地圖, HTML 格式, 符合RWD

這句在做什麼

請 AI 讀取官網，整理出所有頁面和層級，做成一頁網站地圖。這是整個專案的第一步：先盤點現況，再決定要改什麼。

寫法拆解

  • 動作：分析、生成
  • 對象：官網
  • 產出格式：HTML
  • 限制條件：RWD（手機、平板、電腦都能看）

注意

網址少了 ://，AI 還是猜對了，但不要依賴這種運氣。網址最好直接從瀏覽器複製貼上。

2照計畫實作2026/10/14（三）09:16

先出計畫，確認後才動手

原始提示詞
Northgo RWD HTML 網站地圖

Implement the plan as specified, it is attached for your reference. Do NOT edit the plan file itself.

To-do's from the plan have already been created. Do not create them again. Mark them as in_progress as you work, starting with the first one. Don't stop until you have completed all the to-dos.

這句在做什麼

第 1 句之後，AI 先寫出一份計畫。使用者看過、按下「實作」後，編輯器自動送出這段文字，AI 才開始照計畫寫程式。

每一段的用意

  • 第一行：計畫的標題
  • Do NOT edit the plan file：計畫是約定，不讓 AI 自己改
  • Do not create them again：待辦清單已建好，不要重複
  • Don't stop until…：一路做完，不要每步都停下來問

sitemap.html

3追加需求2026/10/14（三）09:24

看到成果後，再補需求

原始提示詞
網站地圖要依選擇的語系, 顯示對應的語系內容；
另外生成一個網站地圖, 樹狀結構, 精簡內容

這句在做什麼

兩件事：一是讓原本的網站地圖可以切換語系，二是另外做一份只列標題的樹狀版。

可以學的寫法

  • 一句話裡有兩個需求，用分號和換行分開，AI 比較不會漏掉其中一個。
  • 「另外生成」說清楚是新增一份，不是改掉原本那份。
  • 第一版做出來之後才發現少什麼，是正常的。小步迭代比一開始寫很長的規格容易。

4追加需求2026/10/14（三）09:34

給參考來源，指明要哪一塊

原始提示詞
參考 https://www.northgo.com/zh-tw/contact 
Locations -- Our global offices
生成一頁世界地圖, 一次顯示全部的辦公室, 也可以選擇局部區域

這句在做什麼

從聯絡頁的「全球據點」區塊取得辦公室資料，畫成一頁世界地圖，可以看全部，也可以只看某個區域。

可以學的寫法

  • 資料從哪來：給完整網址，再貼上區塊標題，AI 就知道要抓頁面上的哪一段。
  • 畫面怎麼動：「一次顯示全部」是預設畫面，「選擇局部區域」是互動功能。把預設狀態和操作分開講。

5分析2026/10/14（三）10:14

大改之前，先請 AI 當顧問

原始提示詞
分析官網 https://www.northgo.com/ , 提出重建及優化方案

這句在做什麼

只要求「提出方案」，沒有要求動手。AI 會說明現在的網站有哪些問題、打算怎麼重做，寫成一份計畫給人審。

為什麼這樣問

  • 重建整個網站會動到很多檔案。先看計畫，比做完才發現方向不對便宜得多。
  • 可以在計畫階段刪減範圍、調整技術選擇，再進入第 6 句。

常用動詞對照

「分析／規劃／提出方案」→ 只產生計畫
「實作／生成／修改」→ 會直接改檔案

照計畫重建整個網站

原始提示詞
Northgo 官網重建方案

Implement the plan as specified, it is attached for your reference. Do NOT edit the plan file itself.

To-do's from the plan have already been created. Do not create them again. Mark them as in_progress as you work, starting with the first one. Don't stop until you have completed all the to-dos.

這句在做什麼

7維運2026/10/14（三）20:25

短短一句也能用

原始提示詞
重啟 local dev

這句在做什麼

晚上回來繼續工作，請 AI 把本機開發伺服器重新跑起來，好在瀏覽器上看網站。

為什麼這麼短也行

AI 會自己去讀 package.json 找啟動指令，也會先停掉還在跑的舊伺服器。專案本身就是上下文，不必每次重講。

留意

這時候還沒有固定的啟動腳本，每次都靠 AI 臨場判斷，做法可能每次不一樣。這個問題到第 13 句才解決。

8維運2026/10/15（四）08:36

一句話串起整個上線流程

原始提示詞
update bump, commit and push to GitHub then Deploy to Cloudflare binding northgo-demo.aidc.work

這句在做什麼

  1. bump：升版本號（這次是 v0.1.1）
  2. commit and push：提交並推上 GitHub
  3. Deploy：部署到 Cloudflare Workers
  4. binding：綁定自訂網域 northgo-demo.aidc.work

可以學的寫法

用 then 把步驟的先後講清楚。網域名稱直接寫出來，AI 就會把它寫進 wrangler.jsonc。

後來的規則改了

部署是對外的動作，出錯會影響所有人。現在 AGENTS.md 規定：AI 不自行部署，只從 main 由人執行 npm run deploy。

9分析2026/10/15（四）11:50

一次講清楚：內容、語言、圖、格式

原始提示詞
規劃 Enquiry-form 作業流程 ,中英文版, 欄位請參考 https://www.northgo.com/contact 
並說明表單流程(SVG格式), 生成HTML簡報

這句在做什麼

規劃「詢價表單」從填寫到送出的流程，做成一份中英文都有的 HTML 簡報。用的是「規劃」，所以 AI 先回一份計畫。

四個條件，缺一個結果就會不同

  • 主題：Enquiry-form 作業流程
  • 語言：中英文版
  • 資料來源：欄位參考官網聯絡頁
  • 格式：流程圖用 SVG，整份用 HTML 簡報

為什麼指定 SVG

SVG 是文字寫成的向量圖，放大不會糊，也能直接改圖上的字，適合要反覆修改的流程圖。

11照計畫實作2026/10/15（四）13:25

中斷了，就說「繼續」

原始提示詞
continue

這句在做什麼

第 10 句的工作沒有一次做完就停了。使用者只回一個字，讓 AI 從停下的地方接著做。

常見的中斷原因

  • 單次回覆長度或執行時間到了上限
  • 網路或編輯器斷線
  • AI 做到一半停下來等人確認

小技巧

同一個對話裡，AI 記得做到哪裡，所以 continue 就夠了。如果是開新對話，就要寫清楚「上次做到哪、還剩什麼」。

14紀錄2026/11/11（三）14:47

把提示詞也當成專案紀錄

原始提示詞
整理本專案全部我輸入的提示詞, 不要修改文字內容,  生成northgo-demo-prompt.md 存入 docs 資料夾。(包括這一句)

這句在做什麼

請 AI 從對話紀錄裡找出使用者打過的每一句話，依時間排好，存成 Markdown 檔。這份簡報就是用這個檔案做的。

三個把範圍講死的條件

  • 「我輸入的」：只要使用者的話，不要 AI 的回答
  • 「不要修改文字內容」：連錯字也保留（例如第 1 句的網址）
  • 「包括這一句」：連正在下的這句也算進去

docs/northgo-demo-prompt.md

從 14 句話學到的六個習慣

1. 先分析，再動手用「分析／規劃／提出方案」先拿計畫，看過再實作。（第 1、5、9 句）
2. 講清楚產出長什麼樣格式、語言、RWD、SVG，條件寫得越具體，越少重做。（第 1、9 句）
3. 給參考來源貼完整網址，再指出頁面上的哪一個區塊。（第 4、9 句）
4. 小步迭代看到第一版再補需求，比一開始寫長規格容易。（第 3、4 句）
5. 重複的事做成腳本同一句話講第二次，就該自動化。（第 7、12、13 句）
6. 對外的動作由人把關部署、推送正式分支，先確認再做。（第 8 句、AGENTS.md）
